# PMBus Calculator v2.5.14

PATCH release：被拒编辑的事务边界修复（P1）、发布文档门禁的真实性修复、
生成物生命周期对齐与移动端触摸合同证据化。

## 诚实陈述

1. **本版本不改变任何 PMBus 数据格式的数学语义。** LINEAR11/LINEAR16/
   DIRECT/HALF 的表示关系、仓库的 `Math.round`（half toward +∞）+ signed16
   clamp 编码策略、signed-zero 与特殊值合同全部不变；这也不是器件精度、
   校准或测量准确度的任何变化。
2. **被拒编辑不再在 blur/Enter 时提交旧草稿（P1 修复）**：v2.5.13 中，被
   DIRECT 4096 字符资源门禁拒绝的粘贴会把当前 focus 事务标为 dirty，而
   受控输入保留上一个短草稿；随后的 blur/Enter 把旧草稿当新候选提交——
   反例 A（`m=1,b=1,R=17`，raw FFFF，近似显示 −1）被改写为 raw 0000；
   反例 B（`m=1,b=0,R=−17`，raw 0001、精确请求 `100000000000000001`、
   误差 +1）raw 不变但精确请求 provenance 被近似值替换、误差显示坍缩为
   +0.000000。现在 blur/Enter 在「最近候选被资源门禁拒绝」时是 commit 层
   no-op（不派发、不改 raw/参数/请求、不清错误），直到新的短候选通过门禁；
   同一 focus 内先前的合法提交保持有效，重复 focus/blur/Enter 不伪造提交，
   模式切换不泄漏标记，显式重输同一合法值仍建立新请求。
   **超长文本仍然被拒绝**：4096 上限不变，这不是放宽长度限制，也不是
   算法更新——变化只是拒绝之后不再把旧显示文本提交为请求。
3. **发布文档门禁修复的是门禁自身的假阳性，不是已发布资产**：v2.5.13 的
   `check:release-docs-commands` 存在四个已证实的检查缺口（expectedMode
   死代码、每 mode 只执行第一条命令、validated 提前填充、子进程脚本路径
   相对父进程 cwd 解析）；两个离线反例（来源 mode 对调、第二条带未知
   flag 的文档命令）在旧 checker 上都返回 ok=true。已发布的 v2.5.13 资产
   经独立核验正确且不可变，本修复不追溯、不改写任何历史结论。
4. **生成物生命周期对齐**：mobile 套件目录（`output-mobile`/
   `report-mobile`）与全部五个 Playwright JSON reporter 产物此前被生成、
   被 .gitignore 覆盖、却不被 cleaner 清理（dry-run 对这四种产物选择为
   空）、被强制暂存时 hygiene 也不拒绝。没有证据表明这些 JSON 曾进入
   正式 Git 历史——这是维护门禁与本地生成物生命周期的缺口，不是仓库
   污染。cleaner 允许清单现覆盖全部产物并对文件/目录伪装显式拒绝；
   hygiene 拒绝被跟踪的 `e2e-results*.json`；>1 MiB 大文件门禁的误导性
   诊断已修正（政策分类是统计数字，不是大小豁免；未引入任何大小例外）。
5. **移动端触摸合同证据化**：`locator.click()` 走 page.mouse，移动端仿真
   不会把它变成触摸——此前 mode tab 与术语气泡外部关闭使用 click 且注释
   声称相反语义。需要证明触摸可用性的路径全部改用
   `locator.tap()`/`touchscreen.tap()`，一次性事件观测探针证明真实
   touch 事件到达（不修改应用行为、不用 synthetic dispatchEvent 冒充），
   360 错误换行断言实测两行几何（bbox 高度 vs 计算行高、无内部裁切），
   并新增 v2.5.14 被拒编辑的触摸失焦双基线。fill/tap 等操作命名与实际
   执行一致；同一套数值 oracle 不在移动端重复穷举。
6. **验证声明去重**：AGENTS/CONTRIBUTING 不再手工复制 verify/verify:light
   命令链（package.json 脚本是唯一真值，手工副本已漏掉 release-docs
   门禁）；RELEASING 的 fresh 重建链不再在同一干净 worktree 内于 verify
   之外原样重跑 verify 已包含的步骤。PR head 的完整验证与 merge 后的
   fresh 独立重建仍是两次不同的可信边界，都不可省略；visual 基线与
   两次确定性资产生成仍单独执行。
7. **删除口径**：本版本不删除任何快照、协议真值、独立 oracle、lockfile、
   现行文档或兼容资源；不进行历史重写、体积瘦身或快照压缩。28 个 visual
   基线、`docs/releases` 发行历史、legacy HTML 兼容入口与规范 manifest/
   cache 边界全部保持原样。
