# PMBus Calculator v2.6.8

PATCH release：PMBus 1.3.1 provenance 可复现 + L16 术语与 PMBus 1.3.1 对齐
（两个同根因切片：此前正式版同时声称「已验证 PMBus 1.3/1.3.1」却没有 1.3.1
manifest 实体，并在 UI 中否认 1.3.1 的正式格式名）。
全部受保护算法（`decode/encodeLinear11`、`findBestLinear11`、`decodeLinear16`、
`encodeLinear16`、`decode/encodeDirect`、`decode/encodeHalf`、`parseVoutMode`、
`calculatePEC`、`encodeUlinear16`、`encodeSlinear16`）零变更；VOUT_MODE bit7、
bits[6:5]、bits[4:0] 位域、raw 单一真值、L16 字节序、持久化格式、copy 合同与
命令元数据零变更；`pmbus-calculator.html` 离线归档零修改。

## 变更范围

1. **PMBus 1.3.1 provenance（P2）**：`document/specifications.json` 补充
   1.3.1 Parts I–III 三条官方实体，`validatedReference` 声称的 "PMBus
   1.3/1.3.1 public archive" 现在可经 manifest 重取并哈希复验。三条记录均来自
   pmbus.org 官方归档 URL，bytes/SHA-256 于 2026-09-03 fresh 下载验证：
   - Part I：178631 B，`68a8063ec2e6badaf2fe8e437f9b2feaf9b7d51889f48b69c8024ff8a51f5ca0`
   - Part II：678599 B，`1717c59615032ea66bf867316e4be076bfa10bf983dab9aff9b7ed4aed2c7ec6`
   - Part III：258382 B，`407605b76545ad368e910f278b6b49984b4386f91dfc5b81f8a2411c98980b8d`
     `scripts/specifications.mjs` 的 `EXPECTED_DOCUMENT_COUNT` 4→7；manifest 契约
     测试断言 7 条记录、1.3.1 三条的 id/revision/landing page；`specs:fetch` 经
     manifest 通道对三部 1.3.1 全部 `already valid`。不跟踪任何 PDF。
2. **L16 术语文案（P2）**：PMBus 1.3.1 Part II 正式命名三种线性格式——§8.4.1
   LINEAR16 Formats、§8.4.1.1 ULINEAR16 Format（直接设置输出电压的命令如
   VOUT_COMMAND 使用 16 位无符号整数）、§8.4.1.2 SLINEAR16 Format（为输出电压
   加减偏移的命令如 VOUT_TRIM 使用 16 位二补码整数）；1.3 旧文统称 Linear
   Mode。glossary 中 ULINEAR16 / SLINEAR16 由 project 来源（含「非 PMBus 规范
   命名」错误断言）改为 `pmbus-spec` 并精确锚定 §8.4.1.1/§8.4.1.2；§13.3/§13.4
   偏移命令语义保留在 detail 正文；LINEAR16 保持 §8.4.1 总类条目并补命名变化
   说明。本产品不声称 PMBus 1.3.1 全 revision 合规（numeric-format subset
   only，不变）。
3. **作用域边界**：仅 manifest/术语单一事实源及其直接消费者与测试；ROADMAP 的
   validated reference 句与 manifest 对齐。命令参考、公式、E2E helper、视觉
   布局零变更。
