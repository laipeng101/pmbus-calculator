# PMBus Calculator v2.6.4

PATCH release：relative ULINEAR16 R=0 合规告警 + DIRECT generic signed 契约
澄清 + legacy 数值偏差披露。受保护算法（`decode/encodeLinear11/16`、
`findBestLinear11`、`decode/encodeDirect`、`decode/encodeHalf`、
`parseVoutMode`、`calculatePEC`）零变更；legacy 归档文件零修改。

## 变更范围

1. **relative ULINEAR16 R=0 非符合性告警（Part II §8.5.2）**：规范要求相对值
   恒为正；L16 页此前只诊断派生溢出/下溢，提交的 `R=0`（raw 0000）无标注。
   view-model 经共享 `resolveL16Relative` 的同一 ratio 解码输出 warning
   `l16-relative-zero-ratio`（warning 级）：数学结果保持精确
   `V_NOM × 0 = 0`，不伪造饱和/错误，物理值复制保持可用；与 `nominal=0`
   decode-only 真零、signed offset（bit7 不参与数学）、absolute LINEAR 互斥，
   标称参考缺失时仍告警。验收向量 `0x98 / 0000 | 12 → R=0, X=0`。
2. **DIRECT generic signed §7.4 契约澄清**：DIRECT 页脚注、README 与
   DOMAIN_MODEL §2.3 明确本页 Y 为 §7.4 generic 16 位有符号（raw=FFFF →
   −1）；§8.1.1/§8.4.3 的 VOUT 无符号正值输出语义属命令/器件上下文，不内置
   unsigned profile、不静默重解释 Y。relative DIRECT（0xC0）/relative Half
   （0xE0）的要求警告与说明卡统一补充「相对值必须为正（§8.5.2）」，0x40/0x60
   保持无该表述。
3. **legacy HTML 已知数值偏差披露**：MIGRATION_MATRIX 记录离线归档
   `findBestLinear11`（`1e-15` epsilon tie、缺 v2.5.10 全范围饱和合同）与
   `encodeHalf`（`Math.round` 非对称舍入 vs IEEE RNE）两处偏差；README
   legacy 段落指向披露并声明 React 应用为数值权威。

## 诚实陈述

1. 本轮只读审查确认 SMBus 3.0 §5.4 仅定义 CRC-8 多项式
   `C(x) = x^8 + x^2 + x^1 + 1` 并把示例方法指向 SMBus 网站，规范内部无
   数值 golden 向量——按「没有向量不改算法」纪律，PEC 回归向量本轮未新增，
   `calculatePEC` 保持既有 number/range 测试。
2. 历史 mutable Release（v2.5.12 及更早）禁止作为手动 Pages 部署/回滚目标的
   停止策略已由 v2.6.2 落档（RELEASING.md 发布纪律）；本轮核实
   `github-pages` environment 的 custom deployment policy 为 `main` +
   `v*.*.*`（无法在不引入逐版本维护负担的前提下技术性排除旧 tag），该治理
   残余风险以 RELEASING.md 文档 + verifier 门禁为既有缓解。
3. `protect-main` ruleset 本轮收窄 `allowed_merge_methods` 为 `["merge"]`
   （仓库 settings 变更，非本仓库文件），与 CONTRIBUTING/RELEASING 的普通
   merge commit 合同对齐；squash/rebase 从未被本仓库使用。
