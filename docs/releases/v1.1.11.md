# PMBus Calculator v1.1.11

PATCH release — release child-process lifecycle、repeated-signal safety、zero-skip completeness 与 canonical Node/npm toolchain（M30）。

## 概述

v1.1.10 对发布管线进行 M30 加固：受控子进程/进程树生命周期、重复信号安全与完整 listener 生命周期、成功声明只在最终协议完成后输出、zero-skip 门禁扩展到九个文件、canonical Node 24.19.0 / npm 11.17.0 工具链，以及 worktree-aware git hooks。**v1.1.10 的线上 Release/Pages 资产本身正确且未做任何回滚、tag 移动或资产覆盖**；全部修复经修改前探针（Probe A–H，未修改 main 的临时 worktree）实证。

## 修复

### 重复信号与完整 listener 生命周期（WP-A）

`process.once('SIGINT'/'SIGTERM')` 在首个信号触发后移除该信号 listener——同信号第二次到达时走默认 raw death（code=null），统一 finally 被绕过、lock 遗留（探针实证 TERM+TERM、INT+INT、三连信号全部 raw death + lock 遗留）。改为显式生命周期管理的 `process.on`：两个 listener 从锁获取前注册、到 `lock.release` 完成**之后**才移除；第一个信号决定最终退出码（SIGINT=130、SIGTERM=143）；后续相同或不同信号只记录 `termination already in progress`，绝不触发默认 raw death。新增真实子进程测试：INT+INT、TERM+TERM、INT+TERM、TERM+INT、三连信号、finalization/lock-release barrier 信号；所有场景非 raw death、first-signal exact code、lock 在全部工作停止前始终存在、零孤儿进程。

### 受控 child/process-tree 生命周期（WP-B）

原 `execFileAsync` 在 timeout 时对直接子进程 SIGKILL 后**立即** reject——Promise 在 child `close` 之前 settle，且不清理孙进程（探针实证：孙进程在 Promise reject 后继续写 SENTINEL，reject 比 close 早 3ms）。重构后：Promise 只在 child `close` 后 settle；timeout 记录 TimeoutError → 请求停止（POSIX 向整个进程组发 SIGTERM）→ 等待 close → 必要时升级 SIGKILL → 仍等待 close → 清理受控进程组/后代 → 最后 reject；`child.kill` 返回 false 不崩溃（仍等 close）；stdin EPIPE/error 被捕获为受控 rejection（探针实证原实现为 unhandled `write EPIPE` 崩溃 + lock 遗留）；维护 active-child registry，runCli 在 lock release 前强制 registry 为空（非空则拒绝释放并保留恢复元数据）；POSIX 使用独立进程组，helper/verifier 的孙进程无法在 Promise settle 后继续写 release 路径；Windows 无进程组、仅杀直接子进程（文档化 fail-closed 边界）。行为测试使用 sentinel 文件与 25 轮 timeout/process-tree stress，不依赖固定 sleep。

### 成功声明只在最终协议完成后输出（WP-C）

`generateAssets` 不再直接打印 `Done:`（探针实证：最终 checkStop 之后、Done 打印之前的 TOCTOU 窗口内信号被 handler 观察到后，`Done:` 仍会打印，且现有测试允许该行为）。现在它只返回 plan、zip size、sums name 与 committed 状态；由 runCli 在以下顺序全部完成后统一打印成功：runLocked 完成 → child registry 归零 → lock release 成功 → signal listeners 移除 → 检查无已观察 signal → 才输出 `Done:` 或 `Transaction recovered successfully`。测试合同改为：只要 handler 观察到 signal，本次运行不得出现任何 `Done:` 或完整成功声明（不只"Done 不早于 handler"）。

### 完整 zero-skip release-security manifest（WP-D）

`SECURITY_TEST_FILES` 从四个文件扩展到九个：新增 `tests/m29-crash-matrix.test.ts`、`tests/m29-release-gates.test.ts`、`tests/m29-signal-protocol.test.ts`、`tests/m30-signal-lifecycle.test.ts`、`tests/m30-child-lifecycle.test.ts`（探针实证：m29-crash-matrix 中一个测试改为 `it.skip` 后门禁仍 exit 0——三个 m29 文件完全不在门禁视野内）。门禁现在实际执行九个文件、total=188 passed=188 failed=0 skipped/todo=0（floor 175 仅为提示，非唯一合同）；每个预期文件必须真实出现在 Vitest JSON report，unexpected suite、missing/renamed/unexecuted、skip/todo/pending 任一非零失败；runner 自测使用 fake vitest fixture，不递归失控；CI 日志打印实际九文件清单与 zero-skip 结果。

### canonical Node/npm toolchain（WP-E）

截至任务执行日核对官方 Node release index（nodejs.org/dist/index.json）：v24 LTS latest = **24.19.0**（npm 11.17.0），无更新 LTS patch。采用：

- `.node-version` / `.nvmrc` → `24.19.0`；`packageManager` → `npm@11.17.0`；
- `engines.node` → `>=22.20.0 <23 || >=24.19.0 <25`；`engines.npm` → `>=11.17.0 <12`；
- `devEngines.packageManager` fail-closed 合同（name=npm、version=11.17.0、onFail=error；Node 版本由 engines.node 与 check:toolchain 强制）；
- CI 主 full verify 通过 `node-version-file: '.node-version'` 使用 Node 24.19.0；compatibility 步骤精确 22.20.0；两个运行时均使用精确 npm 11.17.0（22.20.0 运行时显式 `npm install -g npm@11.17.0`）；Pages 同样读取 `.node-version`；不使用 `22`/`24`/`latest`/`current`/`lts/*`/check-latest；
- `@types/node` 保持精确 `22.20.1`（最低受支持 Node 22 类型表面）；
- 新增 `npm run doctor`（= `check:toolchain`，`scripts/check-toolchain.mjs`）：输出实际 Node/npm 版本，校验 canonical files/package/CI/Pages 一致，不一致非零；已接入 `npm run verify` 与 CI full tier；

### worktree/CI hooks（WP-F）

`postinstall` 从裸 `simple-git-hooks` 改为 worktree-aware wrapper（`scripts/install-git-hooks.mjs`）：主 checkout 正常安装 hooks；linked/detached worktree（`.git` 为文件）跳过并输出清晰信息（探针实证原实现输出 `ENOTDIR: mkdir '<worktree>/.git/hooks'` 且被吞）；CI 环境明确跳过；非 Git 目录跳过。所有 skip 输出普通消息而非 ERROR，npm ci 始终 exit 0 且无 ENOTDIR；不修改其他 worktree 或用户全局 hooks。fixture 测试覆盖 `.git` 目录、`.git` 文件、CI 环境与非 Git 目录四种形态。
