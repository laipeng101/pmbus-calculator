# PMBus Calculator v2.5.0

MINOR release — 格式编码量化误差读数扩展到 LINEAR16 / DIRECT / IEEE 754 binary16，
领域模型重构为可判别结果分类，并修复首轮实现中的 8 项正确性缺陷。

> 2026-08-27 · MINOR（向后兼容）· PMBus Rev 1.3 / SMBus 3.0

## Added

- **全数值模式量化误差读数**：LINEAR16 / DIRECT / HALF 与 LINEAR11 共享同一
  `ErrorDelta` 面板与「格式编码量化误差（请求值 − 表示值）」计算步骤；领域单一来源
  `src/app/quantization-error.ts`，可判别状态 `exact / quantized / saturated /
overflow / special`，严重度只由分类决定（ok / warn / error）。
- 请求来源（provenance）合同：只有显式物理值编码请求才定义误差；任何 raw 位或编码
  解释变更（Hex/bit、DIRECT Y 与系数、payload kind、VOUT_MODE 字节、模式切换）清除
  来源；重复选择当前模式幂等保留。

## Fixed（相对首轮实现的正确性缺陷）

- 无请求来源时隐藏读数，不再伪造 `+0.000000 (0.0000%)`。
- 零分母相对误差显示「—」（DIRECT m=1,b=1,R=−1 请求 0 → +1.000000 (—)），不显示 0%。
- HALF 有限值溢出（65520 → +Infinity）以 overflow/error 呈现；NaN / ±Infinity 请求
  以 special 分类显示，不再静默消失。
- 非零小误差绝不渲染为文本零：|x| ≥ 1e-6 固定 6 位小数，更小值自适应有效数字
  （2^-25 → +0 显示 +2.98023223877e-8 (100.0000%)）。
- 移除无规范依据的跨格式 1e-5 绝对阈值（Part II §7.8/§7.9：设备准确度由产品资料
  规定）；L11/L16/DIRECT 饱和统一为 saturated 分类。
- L16：SLINEAR16 offset 量化不受 bit7 relative 影响（§13.3/§13.4 payload 语义优先）；
  fallback 0x18 读数明确标注；relative ULINEAR16（比值）不显示物理量化误差。
- DOMAIN_MODEL §2.2 与代码/测试的 fallback 矛盾消除；新增 §6 量化语义；
  UI_CONVENTIONS 新增 §15 面板契约。

## 规范结论

- 计算与舍入语义、raw word、字节序与复制格式、命令元数据行为、持久化偏好不变；
- 读数仅描述数字格式的编码量化，不代表器件测量/设置/调节准确度（§7.8/§7.9）。
