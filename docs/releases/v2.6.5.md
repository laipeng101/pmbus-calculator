# PMBus Calculator v2.6.5

PATCH release：L16 Hex 字节序 byte-stream 语义修复（P1）。受保护算法
（`decode/encodeLinear11/16`、`findBestLinear11`、`decode/encodeDirect`、
`decode/encodeHalf`、`parseVoutMode`、`calculatePEC`）零变更；持久化格式、
copy 合同与命令元数据零变更；legacy 归档文件零修改。

## 变更范围

1. **L16 Hex 字节序 byte-stream 语义（P1）**：L16 页 Hex 输入/显示是所选
   字节序的 2 字节字节流——BE（高字节在前）`1234` 与 LE（低字节在前）`3412`
   同指寄存器 word `0x1234`（VOUT_MODE `0x18` 下物理值 18.203125）。此前
   `raw/set-from-hex` 与 `displayedRaw` 仅在 `byteOrder === 'be'` 时交换，
   与 LE/BE 标签相反：BE 输入 `1234` 被反向解码为 `0x3412`（52.0703125），
   且「原始 Hex」显示与实际 raw、LE/BE 字节数组互相矛盾。修复后解析与显示
   共用同一变换（LE 交换、BE 原样）；切换字节序只翻转 Hex 呈现顺序，不改
   raw 与物理值；LE/BE 字节数组、Hex 复制、C 宏与 `rawWordHex` 继续派生自
   未交换 raw word。不足 4 位的输入按数值左补零成规范 4 位后按字节序解释。
2. **同向测试与文案**：固化旧行为的单测与 L16 E2E 断言按字节流语义更新；
   新增 `l16-byte-order` 闭环 E2E 与共享 `leByteStreamText` 助手；
   DOMAIN_MODEL §4、terminology `le`/`be` 条目与页面提示措辞同步
   （BE 不再被描述为「仅用于显示或复制」）。

## 验收向量（VOUT_MODE `0x18`，raw word `0x1234`）

- BE：Hex 输入/显示 `1234`，物理值 `18.203125`，BE bytes `12 34`，LE bytes `34 12`。
- LE：Hex 输入/显示 `3412`，物理值不变，两组 byte 数组不变。
- 切换字节序不改 `state.raw`；L11/DIRECT/HALF 的 Hex 输入保持数值语义。

## 诚实陈述

1. 视觉基线仅 `desktop-dark-l16-stress` 需要更新（该场景在默认 LE 下输入
   `8FC3`，修复后同一输入对应 word `0xC38F`，结果面板文本与位网格随之变化，
   Hex 输入框与「原始 Hex」显示按字节流往返保持 `8FC3`）；已做新旧逐图审查，
   其余 27 张基线（含 3 张不输入 raw 的 L16 场景）确认不变。
2. 短输入（<4 位）的字节序解释采用「数值左补零 → 规范 4 位 → 字节序拆分」
   约定，与 `parseHexStrict` 现有数值语义一致并写入 DOMAIN_MODEL §4；
   4 位规范形下解析与显示互为精确逆变换。
