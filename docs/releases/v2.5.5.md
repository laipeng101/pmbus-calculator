# PMBus Calculator v2.5.5

PATCH release — 补齐 HALF 页对 IEEE 特殊值（NaN / ±Infinity）的 PMBus Part II §7.6.2
操作语义说明；把 VOUT_MODE 的结构合法性、当前可计算性与外部器件数据需求三个维度真正
分离（§8.4.2 Table 3 明列的制造商自定义 `1Eh/1Fh` 不再被标成非法）；并把 v2.5.4 宣称
的 requirement「单一来源」真正收口到四个用户可见表面。

> 2026-08-28 · PATCH（无新功能，语义说明与文案修正）· PMBus Rev 1.3 / SMBus 3.0

## 诚实声明：binary16 数学编码与全部计算结果保持不变

v2.5.5 及之前所有版本的 L11/L16/DIRECT/HALF **数学编码、舍入、饱和、字节序与 NaN
payload raw-lossless 行为全部正确且保持不变**。本版本修复的是两类语义呈现缺口：
HALF 特殊值缺少设备操作语义说明；VOUT_MODE 的合法性/可计算性/外部数据三个维度被
混在一个布尔里导致 `0x3E/0x3F` 被错误标注。本版本不改变任何计算结果。

## Fixed

- **HALF 页遗漏 §7.6.2 特殊值操作语义（P1）**：新增
  `src/app/half-special-semantics.ts` 单一语义来源（finite / NaN / ±Infinity 可判别，
  输出稳定 machine id、severity、send/read 双解释、spec ref），HALF 页在当前 raw word
  为特殊值时显示 §7.6.2 特殊值卡；raw Hex 解码与物理值编码两条真实路径都可见，有限值
  （含 ±0）不显示：
  - NaN：作为写入数据——设备必须按 invalid data 处理、声明 communications fault 并按
    §10.8 响应；作为设备读回值——设备可在值不可用时返回 NaN；
  - +Inf / -Inf：作为写入数据——设备分别解释为正 / 负满量程；作为设备读回值——分别
    表示测量通道正 / 负方向饱和；
  - 卡片同时列出两种解释（不猜测实际命令方向），并注明「这是 PMBus 操作语义，不代表
    本页已发生总线通信；binary16 数学换算保持不变」；设备读回主机写入值时必须返回
    精确原始编码（含特殊值）也在卡内说明；
  - 量化误差分类不变：主动输入特殊值 = `special/warn`；有限 `65520` 溢出 =
    `overflow/error`。有限溢出编码出的 +Inf word 同时显示 overflow/error 读数与
    §7.6.2 卡是正确形态——两个表面回答不同问题，不合并成一个状态。
- **VOUT_MODE 结构合法性与可计算性分离（P1/P2）**：§8.4.2 Table 3 明列 `1Eh/1Fh`
  为 PMBus device manufacturer specific VID Code Type，字节结构合法、电压映射必须来自
  器件资料。此前 `analyzeVoutMode` 的 `profile-required`（`isLegal=false`）被
  view-model 直接映射为 `structureLegal=false`，正式页面给配置摘要和状态 chip 加了
  代表非法结构的 alert 标志/class。现在：
  - requirement 判别式新增 `structureLegal`：valid 与 profile-required 为 true；
    not-used（00h）/ reserved / relative+VID / 参数非零仍为 false；
  - view-model `structureLegal` 从判别式取值，新增正交 `requiresExternalData`
    （= 需 m/b/R 或需 VID 表）；`0x3E/0x3F` 不再出现非法 alert 标志/class，仍保留
    「需器件资料」warning 与「制造商自定义」文案；
  - Normalize 对 `0x3E/0x3F` 保持字节不变（Table 3 明列配置无需规范化）；
  - L16 页对 `0x3E/0x3F` 继续 fail closed，阻断原因保持「合法但缺 profile」，
    不称「不合法」。
- **requirement「单一来源」真正收口（P2）**：v2.5.4 的
  `resolveVoutModeRequirement` 实际只被 status 文本消费；InfoPanel、explanation 与
  calculation steps 仍自行 switch `format`/`status`，已出现两处可观察分叉。现在四个
  表面（status / InfoPanel / explanations / steps）全部 switch 在同一判别式的
  `req.id` 上：
  - `0xC0`（相对 DIRECT）的 InfoPanel 警告本身同时写明 m/b/R 系数与 VOUT_COMMAND
    标称参考值（§7.4 + §8.5.2）；
  - `0x3E/0x3F` 计算步骤改用专门 `vout-mode-vid-profile` 分支，不再落入
    `vout-mode-invalid`；
  - E2E helper 从「所有表面拼接成一个字符串检查一次」改为逐表面独立断言；unit
    truth table 对 0..255 穷举分离结构合法性、可计算性与外部数据要求，并对
    `0xC0`/`0xE0` 逐表面断言必需文案。
