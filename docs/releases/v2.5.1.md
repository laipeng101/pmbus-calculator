# PMBus Calculator v2.5.1

PATCH release — 修复 SLINEAR16 offset 在 bit7=1（如 VOUT_MODE 0x98）时的物理值输入
不可达（P1-A）与手动 Y_s 编辑后旧量化请求未失效（P1-B），并同步领域文档契约。

> 2026-08-27 · PATCH（无新功能，行为修正）· PMBus Rev 1.3 / SMBus 3.0

## Fixed

- **0x98 + SLINEAR16 offset 物理输入不可达（P1-A）**：编码顺序、可编码范围与 UI 入口
  改为 payload 上下文判定（Part II §13.3 VOUT_TRIM / §13.4 VOUT_CAL_OFFSET；bit7 属于
  §8.5 相对阈值命令组，不参与该 payload 数学）。修复后：物理值输入与 Y_s 编辑器可见、
  nominal 阻断卡不再出现、`3.3 → 0x034D`（3.30078125，quantized/warn −0.000781）、
  `200 → 0x7FFF`（127.99609375，saturated/error）、范围文案 `-128..127.99609375`；
  relative ULINEAR16（比值）合同不变（仍需 VOUT_COMMAND 标称参考值、不提供反向编码）。
- **手动 Y_s 编辑后旧请求未失效（P1-B）**：提交性 `l16/set-slinear-y` 现在与其他 raw
  变更一致清除 `valueRequest`，误差面板与计算步骤立即隐藏；非法/过渡输入不改变 raw、
  不清除仍有效请求。
- **领域文档契约纠偏**：DOMAIN_MODEL §2.2 的 relative LINEAR 拒绝规则限定为
  ULINEAR16 比值语义，SLINEAR16 offset 编码顺序/范围/bit7 边界成为明确契约；§6.1
  provenance 失效清单加入手动 Y_s；UI_CONVENTIONS §15 记录 payload 上下文入口与
  手动失效验收要求。
