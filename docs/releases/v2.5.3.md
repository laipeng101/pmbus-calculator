## 诚实声明：v2.5.2 的数值行为有效，文案有误

v2.5.2 移除隐式 0x18 回退后的**数值 fail-closed 行为是正确的且保持不变**；但它的
阻断卡把 Part II §8.4.2 支持的 VID 数据格式错误表述为「输出电压相关命令禁止使用
VID」，同时 raw 位域仍按 payload 下拉标注为 LINEAR16 的 V/Y。本版本只纠正规范解释、
状态建模、帮助文本、位域图例与测试矩阵，不改变任何计算结果。

## Fixed

- **VID scope 必须 payload/命令感知（P1）**：正式页 ULINEAR16 + `0x20`/`0x3E` 会得到
  「输出电压相关命令禁止使用 VID」的结论，不符合 Part II §8.4/§8.4.2——VID 是规范
  支持的输出电压数据格式。全局 `vidProhibited` 布尔被可穷举的 discriminated contract
  （`src/app/l16-payload-contract.ts`）取代，UI 文案、输入可用性、结果、公式、步骤、
  warning 级别与测试共同消费同一解析结果：
  - `vid-profile-required`（绝对 VID + 数值 payload）：VID 合法但本页未选定 VID 表 /
    产品 profile，无法换算 code ↔ 电压，不借用 LINEAR16 指数 N；制造商自定义 code
    （raw `0x3E`/`0x3F`）注明映射必须来自器件资料，不称保留或禁止；
  - `vid-offset-prohibited`（绝对 VID + SLINEAR16 offset）：VOUT_TRIM /
    VOUT_CAL_OFFSET 被规范禁止（§13.3/§13.4），新增 error 级提示，并明确**禁止范围
    仅限这两条二补码偏移命令**；
  - `vid-relative-invalid`（相对 + VID，如 `0xA0`）：字节组合无效（§8.5.3）；
  - `direct-profile-required` / `half-unsupported-in-l16`：DIRECT 需 m/b/R 系数
    （§7.4）、IEEE Half 是合法格式但本页不实现解释（§8.4.4）；均不猜测 N、不借用 0x18；
  - `reserved-or-invalid`：DIRECT/Half 参数非零等非法配置。
- **非 LINEAR raw word 图例中性化（P1/P2）**：`getBitRegions` 接收实际共享字节，
  任何非 LINEAR 状态的 16 位位域不再显示「数值 V [15:0]」/「有符号值 Y [15:0]」，
  改用中性 `raw word [15:0]（未按 LINEAR16 解释）`；payload 下拉切换不复活 V/Y
  图例；LINEAR 字节恢复 payload-specific 图例。
- **文档纠偏**：DOMAIN_MODEL §3 与 UI_CONVENTIONS §15 登记新契约并禁止旧的全局禁令
  文案回归；ROADMAP M38 历史 fallback 摘要标注已被 v2.5.2 supersede。
