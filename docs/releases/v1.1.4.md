# PMBus Calculator v1.1.4

维护性 PATCH 发行：不含新产品功能。本版本汇总 v1.1.3 之后合入 main 的兼容性修复、验证与发布基础设施加固，以及本次 TypeScript 门禁与发布合同强化。

发布渠道：GitHub Release（不发布 npm 包）。

## Fixed

### TypeScript 验证门禁真实性（M23）

- `npm run typecheck` 从对 solution 根配置执行 `tsc --noEmit`（实际受检文件数为 0，src/tests/Playwright 配置中的类型错误全部漏检）改为 `tsc -b` 构建模式，真实检查应用源码、Vite/Node 配置、单元测试、E2E 测试与全部 Playwright 配置；CI 日志可见 app/node/tests 三个项目的构建记录。
- 新增 `tsconfig.tests.json`（strict、noUnusedLocals/Parameters、Node + Vitest globals、allowJs 边界）并由根 tsconfig references 引用；新增 `tests/typecheck-contract.test.ts` 结构性回归测试锁定该合同，防止门禁退回空检查。
- `@types/node` 成为直接 devDependency，不再依赖传递依赖偶然提供类型。
- 四个 mjs 脚本的导出边界补精确 JSDoc 类型；修复 strict 检查暴露的 59 处测试类型错误，包括两处真实测试缺陷（`documentPdfs` 过期断言、`page.goto` 返回值 null 处理）。PMBus 算法、命令元数据与 UI 行为零改动。

### 发布合同与发布流程

- 新增完全离线的 `npm run check:release-contract`：以 `package.json` 版本为唯一来源，校验 lockfile、CHANGELOG、`docs/releases/vX.Y.Z.md`、双 README 的 stable/live/Release/SHA256SUMS 链接、ROADMAP 声明与 Release 资产命名（`pmbus-calculator-vX.Y.Z-web.zip`、`SHA256SUMS.txt`）一致性；成功与失败场景均有单测；接入 `npm run verify` 与 full CI。
- `docs/RELEASING.md` 重写为 M19-B 后的正确流程：PR 最新 head full CI 成功 → 记录 `checked_sha`/`checked_tree` → 普通 merge → merge tree 与 `checked_tree` 一致即验证完成（不重复 CI），不一致才 workflow_dispatch full CI；tag 之前必须在精确 merge SHA 的干净 detached worktree 中完成全量验证与 zip/checksum 校验。删除已失效的“merge 后等待 main push CI”要求。
- CI：full tier 的 Type check 运行真实 `tsc -b`；Node 24 次级验证升级为 typecheck + 单测。

### 仓库卫生与规范分发（v1.1.3 后合入 main）

- 仓库卫生门禁与制品政策：tracked 文件禁令（构建产物、日志、PDF 等）、按 blob 计算树大小、clean preflight 安全检查跨平台化。
- 第三方规范 PDF 移出 Git tree：provenance、官方 URL、字节数与 SHA-256 集中维护在 `document/specifications.json`，下载限制在白名单 host、流式写入完整性、deadline 提交门禁；PDF 按需下载到 ignored cache。
- Tailwind 构建范围可复现：`source(none)` + 显式 `@source` 隔离生产扫描范围，canary 回归防止非生产工具类泄漏进发行 CSS。

### CI 可靠性与受保护 main

- fail-closed light/full CI 分级（纯文档任务跳过重型门禁，未知变更一律 full）。
- Playwright report 仅在产出它的测试步骤确实运行并失败时上传。
- `protect-main` ruleset：main 变更必须经 PR、required check、strict up-to-date、禁 force push 与删除；merge 后以 `checked_tree` 审计替代第二次完整 CI。
- Vitest 4 与 `@vitest/coverage-v8` 成对升级（移除弃用 glob 依赖链）、Node engines 收紧为 22/24 两条 LTS、CI 增加 Node 24 次级验证。

### 输入交互与可访问性（v1.1.3 后合入 main 的用户可见修复）

- 输入校验：统一整数语法，`1e2`、`1.5`、`0x10`、`12abc` 等宽松转换在 L11 N/Y、DIRECT Y、DIRECT m/b/R 一律拒绝；编辑过渡态不逐键报错；非法终值显示字段级可见错误并保留 draft，修正后同步清除 `aria-invalid` 与旧 draft；DIRECT 系数错误按字段隔离且跨模式保留。
- 键盘：`Ctrl+1..4` 快捷键仅在非编辑上下文生效，不再丢 draft 或抢焦点。
- CommandPicker（W3C APG combobox pattern）：选项为不进 Tab 顺序的语义元素；`aria-selected=true` 恒等于 `aria-activedescendant` 指向的 active option；ArrowUp/ArrowDown 首尾停止不循环；Tab/Shift+Tab 关闭弹层并把焦点移到 trigger 的逻辑相邻控件；Escape 取消并恢复 trigger 焦点；焦点移出时关闭弹层且不抢焦点；非空搜索零匹配显示「无匹配命令」状态且 Enter 安全 no-op；清空搜索恢复选项、active selection 与滚动位置。

## 已知限制

- READ_EIN 字节数呈现与 DIRECT device-datasheet presets 仍需真实器件数据手册，保持禁用。
- 部署 smoke 的 8 个 deployment tests 需要 `DEPLOYMENT_URL` 环境变量；在 Pages 发布流程内自动执行。
