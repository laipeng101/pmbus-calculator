# PMBus Calculator v2.6.6

PATCH release：legacy `PMBusMath.encodeLinear16` 指数语义修复（P2）。除该函数外，
其余受保护算法（`decode/encodeLinear11`、`decodeLinear16`、`findBestLinear11`、
`decode/encodeDirect`、`decode/encodeHalf`、`parseVoutMode`、`calculatePEC`、
`encodeUlinear16`、`encodeSlinear16`）零变更；持久化格式、copy 合同、字节序
与命令元数据零变更；`pmbus-calculator.html` 离线归档零修改（其保留的历史
raw-clamp 行为按归档政策原样保留，差异已在 MIGRATION_MATRIX 披露）；产品 UI、
视觉基线与 Pages 外观不变。

## 变更范围

1. **`encodeLinear16` 指数语义（P2）**：该导出 helper 此前忽略指数参数 `n`，
   只返回 `clamp(v, 0, 65535)`，与同对 `decodeLinear16`（`X = V × 2^N`）不对称，
   也不符合 PMBus Part II §8.4.1 ULINEAR16 编码方向（`Y_u = X / 2^N`）——例如
   `encodeLinear16(1, -8)` 返回 `1` 而非 `0x0100`，且可能泄漏非整数 payload。
   现在按既定舍入合同实现 `round(X / 2^N)` 后 clamp 到 `0..65535`，与 canonical
   `encodeUlinear16` 一致。生产 L16 编码路径（`src/app/reducer.ts` 等）本就使用
   `encodeUlinear16`，本修复不改变任何产品行为。
2. **测试与披露**：新增 ULINEAR16 编码方向 golden（含 §8.5.2 官方算例）、非零
   正/负 N、舍入、饱和、round-trip（半 LSB 误差合同）与 `encodeUlinear16`
   一致性覆盖；MIGRATION_MATRIX 新增 legacy 归档第三处已知数值偏差披露；
   DOMAIN_MODEL/命令元数据无需变更。

## 验收向量

- 编码方向：`encodeLinear16(1, -8) = 0x0100`；`encodeLinear16(12, 2) = 3`；
  `encodeLinear16(3.3, -10) = 3379`（§8.5.2 官方算例，解码回
  `3379 / 1024`）。
- N=0 clamp 行为不变：`encodeLinear16(70000, 0) = 65535`、
  `encodeLinear16(-1, 0) = 0`。
- 饱和与下界：`encodeLinear16(70000, -8) = 0xffff`；
  `encodeLinear16(0.001, -8) = 0`；
  `encodeLinear16(65535 × 2^-8, -8) = 0xffff`。
- round-trip：非饱和 payload 经 `decodeLinear16` 解码误差 ≤ 半 LSB（`2^N / 2`）；
  对同组输入与 `encodeUlinear16` 逐点一致。
