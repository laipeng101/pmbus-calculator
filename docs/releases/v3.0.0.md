# PMBus Calculator v3.0.0

MAJOR release：canonical Raw Word 领域模型重构（breaking）。`state.raw` 从此
是 L11 / L16 / DIRECT / HALF 全部数值模式唯一的 canonical 无符号 16-bit raw
word；v2.6.5 引入的「L16 主 Hex 是所选字节序的 byte stream」合同被删除。
全部受保护算法（`decode/encodeLinear11`、`findBestLinear11`、
`decodeLinear16`、`encodeLinear16`、`decode/encodeDirect`、`decode/encodeHalf`、
`parseVoutMode`、`calculatePEC`、`encodeUlinear16`、`encodeSlinear16`）与
VOUT_MODE 位域、payload discriminated contract、命令元数据零变更；
`pmbus-calculator.html` 离线归档零修改。

## 为什么是 MAJOR（不兼容变更）

RELEASING「稳定公共契约」中的 raw word、字节序、复制格式与已持久化偏好四项
全部变更：

1. **旧合同**（v2.6.5–v2.6.8）：L16 模式 + LE 字节序时，主 Hex 输入/显示是
   低字节在前的 2 字节 byte stream——输入 `3412` 得到 raw `0x1234`；同一界面
   上位网格、`rawWordHex`、C 宏却始终是未交换 raw word，Hex 字段可能显示
   `8FC3` 而位网格是 `C38F`。字节序通过 `AppState.byteOrder` +
   `byte-order/set`（L16 下拉）与 `copy.endian` + `copy/set-endian`
   （「Hex 复制顺序」偏好）两个抽象存在。
2. **新合同**：主 Raw Word 永远是 canonical 数值原字——`3412` 在包括 L16 在内
   的全部模式下就是 `0x3412`，`parse(formatRawWordHex(raw)) === raw` 对合法的
   全部 16-bit raw 成立，且不受任何 byte order 偏好影响。
3. **旧偏好存储**：`pmbus-calculator:byteOrder` 键与 copy JSON 的 `endian`
   字段不再读取；旧值被显式忽略，不会换位新 Raw Word、不产生非法 state
   （单元与 E2E 回归测试锁定）。

## 领域模型（canonical Raw Word / serialization 分层）

```
                ┌→ format interpretation → physical value
canonical raw ──┤
                └→ serialization → byte sequence
```

- raw identity 层：主 Raw Word Hex、位网格、公式操作数、decode/encode、
  Raw Word 复制、C 宏。
- serialization 层：SMBus / PMBus Wire Bytes（低字节在前，SMBus 3.0 §6.5.4
  写事务明示 low byte first、§6.5.5 读事务图中 Data Byte Low 在前、PMBus
  Part I §5.6.3.2.4 确认 DS=0 默认最低有效字节在前）与 MSB-first 字节
  （高字节在前，仅显示/对照表示，不是另一种合法 wire order）。
  view-model 字段 `rawBytesLE`/`rawBytesBE` 更名为 `wireBytes`/`msbFirstBytes`。
- 改变任何复制/显示偏好不得改变 `state.raw`、主 Raw Word、位网格、公式 raw、
  decoded/encoded value、量化 provenance 与 C macro raw。

## 复制模型（显式 representation actions）

| 动作           | 输出（raw 0x1234 示例） | 说明                                 |
| -------------- | ----------------------- | ------------------------------------ |
| Raw Word       | `0x1234`（或 `1234`）   | canonical 数值，仅受 0x 前缀偏好影响 |
| Wire 字节      | `0x 34 12`              | SMBus/PMBus 线上顺序（低字节在前）   |
| MSB-first 字节 | `0x 12 34`              | 高字节在前表示，仅对照               |
| 物理值         | 当前物理值文本          | 合同不变（DIRECT 精确回录语义保留）  |
| C 代码         | `#define … 0x1234`      | 始终 canonical raw word              |

0x 前缀与字节空格偏好保留；「Hex 复制顺序」（LE/BE）偏好组删除。

## Breaking examples

```text
old: L16 LE 下主 Hex 输入 3412 → raw 0x1234（字节流解释）
new: 主 Raw Word 输入 3412 → raw 0x3412；raw 0x1234 的低字节在前字节
     序列 34 12 在 Wire Bytes 行单独显示/复制

old: L16 LE 下 raw 0xC38F 的主 Hex 显示 8FC3（与位网格 C38F 矛盾）
new: 主 Raw Word 恒显示 C38F，与位网格、公式、复制、C 宏一致

old: "Hex（LE/BE）" 复制按钮 + 全局「Hex 复制顺序」偏好
new: Raw Word / Wire 字节 / MSB-first 字节 三个显式复制动作
```

## 验收向量（golden）

- L16（VOUT_MODE 0x14，N=-12）：12 V → raw C000，Wire `00 C0`，
  MSB-first `C0 00`；raw BFFF → 精确值 11.999755859375（显示 12 位有效数字
  11.9997558594），Wire `FF BF`。
- L11：raw C100（N=-8、Y=256 → 1.0），Wire `00 C1`，MSB-first `C1 00`。
- DIRECT（m=1,b=0,R=0）：raw 1234 → Y=+4660，Wire `34 12`，MSB-first `12 34`。
- HALF：raw 3C00 → 1，Wire `00 3C`，MSB-first `3C 00`。
- serialization 不变量：`wireBytes = [low, high]`、`msbFirstBytes` 为其逆序；
  复制/显示偏好翻转不改变 raw、位网格、物理值、公式与 C 宏
  （`src/app/canonical-raw-word.test.ts` 全模式锁定）。
