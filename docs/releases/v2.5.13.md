# PMBus Calculator v2.5.13

PATCH release：DIRECT 输入资源边界统一、E2E 执行去重与发布链完整性加固。

## 诚实陈述

1. **本版本不改变任何 PMBus 数据格式的数学语义。** LINEAR11/LINEAR16/
   DIRECT/HALF 的表示关系、仓库的 `Math.round`（half toward +∞）+
   signed16 clamp 编码策略、signed-zero 与特殊值合同全部不变；这也不是
   器件精度、校准或测量准确度的任何变化。
2. **统一 DIRECT raw lexeme 资源边界（P2 修复）**：v2.5.12 的 4096 字符
   上限在 UI 按 raw 长度判断、在 exact parser/reducer 防线却先 `trim()`
   再查 trimmed 长度——直接派发 `1000000 个空格 + "1"` 被 trim 后接受，
   raw 改写为 1 且 provenance 驻留百万字符原始请求（该路径在普通 UI 下
   不可达，因此按 P2 处理）。现在边界度量是调用方原始字符串长度（任何
   trim 之前），UI 输入门与 reducer/exact parser 共享同一防线：
   `ValueInput.handleChange` 在写入 draft state 之前拒绝超长输入
   （超长粘贴不再进入 React state，受控输入保留旧草稿），reducer 直接
   派发超长文本是严格 no-op，被接受的 provenance 文本 ≤4096。短输入的
   空白语义（首尾空白、`0e-400`/`-0.0e-999` 等任何指数下的 true zero）
   不变；刻意不使用 HTML `maxlength`（避免粘贴静默截断）。
3. **E2E 语义只跑一次，移动端合同显式化**：默认 Playwright 套件曾以
   desktop+mobile 双 project 无选择地完整执行两遍（292 逻辑用例 →
   584 次执行），多数 spec 内部自设 viewport，双跑无独立覆盖。现在默认
   套件单 project 跑一次（293 tests），真实移动端风险集中在显式
   `mobile-contract` 套件（11 tests，Pixel 7 仿真：390/360 布局与无横向
   溢出、触摸点击、术语气泡、命令参考、错误文案换行、逐格式转换
   smoke），独立 config 承载并进入 CI 与 `npm run verify`。1 MiB 浏览器
   paste 从 E2E 移除（兆字节拒绝由纯函数/reducer 单测锁定）；逻辑用例
   标题守恒，old→new 映射随 PR 记录；不使用 skip/弱断言。
4. **未来 Release 平台强制不可变**：仓库设置 immutable-releases 已启用
   （enablement 时点之后创建的 Release publish 后 API 报告
   `immutable: true`；不追溯、不修改 v2.5.12）。RELEASING.md 增加 tag 前
   平台前置复核与 publish 后 `immutable: true` + `gh release verify` /
   `verify-asset` attestation 复核。设置启用属于人工授权步骤，Pages
   workflow 权限不变（`contents: read`、`pages: write`、`id-token: write`）。
5. **release 操作文档命令合同进入轻量 CI**：
   `npm run check:release-docs-commands` 从 `docs/RELEASING.md`（draft）与
   Pages workflow（published）提取 `verify-downloaded-assets.mjs` 真实
   调用，在离线 zip/metadata fixture 上执行生产脚本——文档 argv 必须
   exit 0，位置参数（PR #74 回归）与非法 `--mode` 必须 exit 2。该门禁在
   CI 两个 tier 都运行；普通叙述性 docs 仍为 light tier。
6. **仅移除经证明无引用的配置**：`.depcheckrc`（90 bytes）删除前经
   package.json/package-lock/workflows/CONTRIBUTING/docs 全量引用审计
   （0 命中）。不进行任何历史重写、体积瘦身或快照压缩：28 个 visual
   基线、`docs/releases` 发行历史、legacy HTML 与规范 manifest/cache
   边界全部保持原样。

  ≥ `vite.config.ts` 阈值；
- default E2E：293 passed（单 project）；mobile contract：11 passed；
  visual：28 基线零更新；release E2E：1 passed；
- default E2E 本地 3 次计时中位数 132s → 77s（修改前/后各 3 次）；
- `npm run verify`（含新增 release-docs-commands 与 mobile E2E）exit 0；
  audit 0 high。

## 兼容性

- PATCH 级别：无持久化偏好、复制格式、raw 字节序或命令元数据行为变化。
- 唯一可观察行为变化是上述超长输入的拒绝时机（从「进入草稿后报错」
  提前到「进入草稿前拒绝」）与 DIRECT reducer 对 padded 超长派发的
  no-op 化——两者都是 v2.5.12 声称的「共享防御边界」合同的实际落实。
