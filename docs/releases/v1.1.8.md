# PMBus Calculator v1.1.8

PATCH release — Release transaction commit semantics、recovery integrity、真实并发/故障注入与零 skip 验收（M27）。

## 概述

v1.1.8 对 v1.1.7 的发布管线进行 M27 加固。**v1.1.7 的线上 Release/Pages 资产本身正确且已重新验证**，本次未做任何回滚、tag 移动或资产覆盖；修复的是 v1.1.7 中经修改前探针实证的六项管线缺陷：--recover 绕过锁与完整性校验、部分备份删除导致新旧资产丢失、symlink 测试实际始终 skip、rollback 测试未达 publish 阶段、behavioral contract fallback 假通过、clean 与文档矛盾。

## 修复

### 统一锁域（WP-A）

普通生成、--force、--recover 使用同一原子互斥锁；--recover-lock 是唯一可在未持锁时操作锁文件的命令。--recover 先 acquireLock、在 try/finally 中执行恢复、release 失败使 CLI 非零。cleaner 发现锁时 fail closed 并在删除任何 release 目标前停止；锁文件从清理目标移除；RELEASING.md 同步修正"clean 同时清理锁"的错误描述。并发验收由 25 个真实子进程调用真实导出函数完成，严格一个 winner。

### 锁创建与释放错误完整性（WP-B）

acquireLock 在成功 open 后遇到 write 失败、short write 或 close 失败均关闭 fd 并只清理由本次创建的 lock inode（fstat/lstat dev+ino 所有权校验）。release() 不再吞掉 unlink/read/parse 错误，失败抛出 LockReleaseError。生成成功但锁释放失败时 CLI 非零并明确提示资产已生成但锁未释放。新增 SIGINT/SIGTERM 行为测试。锁元数据 schemaVersion/startedAt/nonce 校验，未知 schema 禁止自动恢复。

### 事务 commit point 与故障恢复（WP-C）

显式状态机 STAGING_VERIFIED → OLD_OUTPUT_BACKED_UP → NEW_OUTPUT_PROMOTED → NEW_OUTPUT_VERIFIED → COMMITTED → BACKUP_CLEANED。COMMITTED 之后 backup 删除失败不删除新 output、不覆盖、保留残余并要求显式 recovery。versioned journal（schema/nonce/version/state/output/backup/new-old SHA-256）以临时文件 + fsync + 原子 rename 更新。12 个具名 failpoint 全部有阶段断言测试，禁止以 createHash 调用次数冒充注入。

### Recovery 完整性（WP-D）

backup 恢复前深度验证：恰好两个普通文件、SHA256SUMS 单行匹配、checksum 一致、verify_release_zip.py 通过、内部版本合同通过。output 与 backup 并存时按 journal 状态裁决（PRE_COMMIT 恢复旧 backup / COMMITTED 保留新 output 仅清 backup / journal 异常拒绝人工审计）。多 backup、损坏 backup、无 journal 双侧并存一律拒绝。

### artifact contract 真实执行路径（WP-E）

动态 import fallback 移除，加载失败即 fail closed。buildReleasePlan(version) 成为唯一计划实现；generator 只消费 plan，禁止本地命名模板与直接 assetNames 调用。runCli 支持注入 repoRoot，fixture 以真实 CLI 运行正负向场景。

### symlink、并发与 Python helper（WP-F）

symlink 能力在测试注册前同步探测，canonical 环境 symlink/FIFO/helper 安全测试零 skip。Python helper 对原始路径 O_NOFOLLOW 打开、fstat dev+ino 身份比对、循环读取处理 short read、长度/身份变化即失败，并在任何失败时清除半成品 zip。

### 测试真实性（WP-G）

expect(true) 式占位断言删除；catch 全部 unknown narrowing；每个 failpoint 测试断言触发名与阶段 trace；full CI 新增 Linux generator/security 专项步骤（npm run test:release-security），零 Playwright 依赖，任一 skip 即失败。
