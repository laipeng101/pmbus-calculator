# PMBus Calculator v1.1.10

PATCH release — Release durability、signal determinism、recovery state consistency 与 security gate completeness（M29）。

## 概述

v1.1.10 对 v1.1.9 的发布管线进行 M29 加固。**v1.1.9 的线上 Release/Pages 资产本身正确且未做任何回滚、tag 移动或资产覆盖**；修复的是 v1.1.9 中经修改前探针（Probe A–G，全部在未修改 main 的临时 worktree 运行）实证的四类缺口：zero-skip 门禁只运行两个测试文件、父目录 fsync 错误被错误吞掉（EIO 注入后仍成功发布）、signal 处理依赖最多 10 次 setImmediate 的时序启发式（Done 可在 handler 观察到信号前打印）、恢复与 journal 存在 crash window（PRE_COMMIT 恢复在验证 oldSha256 前已删除 output、移动 backup）。

## 修复

### zero-skip security gate 完整覆盖（WP-A）

新建 `scripts/release-security-test-contract.mjs` 作为共享清单 `SECURITY_TEST_FILES`，runner 与合同测试引用同一清单，不得分别硬编码。门禁现在实际执行四个文件：`tests/prepare-release-assets.test.ts`、`tests/zip-helper-security.test.ts`、`tests/m28-recovery.test.ts`、`tests/run-release-security-tests.test.ts`。清单文件缺失、重命名或未执行时 fail closed；报告必须精确包含四个预期 suite（多余 suite 也失败）；skipped/todo/pending 任一大于 0 即非零；CI 日志列出实际覆盖的四个文件与 zero-skip 结果。runner 自身测试加入门禁时使用 fake vitest fixture，不产生无限递归。

### 确定性 signal/lock 协议（WP-B）

删除 bounded 10×setImmediate flush loop。Python helper/verifier 子进程改为 async spawn；`generateAssets` 与 `recoverTransaction` 在每个事务 stage 边界（每次 journal 写、每次子进程完成）检查注入的终止状态：signal 被 handler 观察到后不进入新的 transaction stage、不打印 `Done:` 或任何完整成功声明。INIT journal 在任何长时子进程前持久化，因此信号到达任何时点都留下 `--recover` 可解析的 journal。SIGINT 精确返回 130、SIGTERM 精确返回 143；lock 在所有写/rename/子进程停止前不释放；第二个 generator 在第一进程完全停止前无法获得锁。Node 22.20.0 与 24.0.0 各自 100 轮（50×SIGINT + 50×SIGTERM）stress：0 flaky、0 skip。

### 目录 durability fail-closed（WP-C）

新增 `fsyncParentDirectorySync`。错误分类：EINVAL、ENOTSUP、EOPNOTSUPP（经实测与文档说明的"平台不支持目录 fsync"）降级为 note；EIO、ENOSPC、EROFS、EBADF、未知错误与 close 失败抛 `DurabilityError`——保留 journal/backup/lock 恢复信息、返回非零、不得报告完整成功。覆盖全部六个 mutation boundary：journal temp write/fsync/close、journal rename 后 parent fsync、output→backup rename 后、staging→output promotion 后、backup 删除后、journal unlink 后。

### 恢复前验证与 crash-consistent journal（WP-D）

PRE_COMMIT + backup 恢复在删除或 rename 任何路径之前，将 backup 的 zip+sums 实际 hash 与 journal.oldSha256 比较；不匹配时零磁盘 mutation（无 rm/rename 被调用），journal/backup/output 全部原样保留。journal 写入顺序重排：`OLD_OUTPUT_BACKUP_INTENT` 在 output→backup rename 之前持久化（oldSha256 从尚未触碰的 output 计算）；hash 先填充再持久化 `STAGING_VERIFIED`；`STAGING_GENERATED` 允许空 hash（state-dependent 校验）。14 个 crash matrix failpoint（13 个 force 场景 + 首次发布）逐一验证：磁盘 journal 可被 validator 解析、`--recover` 可重复运行、第二次 recovery 幂等、失败时不产生 journal 指向不存在 backup 的状态。

### 统一 ZIP entry contract（WP-E）

共享 fixture `tests/fixtures/zip-entry-contract.json` 驱动三层一致校验：JS `validateZipEntry`、`scripts/_zip_helper.py`、`.github/workflows/scripts/verify_release_zip.py`。Windows drive absolute/drive-relative（`C:/`、`C:\`、`C:`）与 UNC（`//`、`\\`）三层全部拒绝；`'.'` 段、空段、backslash、control 字符、node_modules/src、.map 三层一致拒绝。helper 直接调用时 fail closed 且失败后不留 partial ZIP。

### runner 私有临时目录与清理失败（WP-F）

报告位于 `fs.mkdtempSync` 创建的随机私有目录（0o700），不再使用可预测的 `/tmp/release-security-tests-${pid}.json`。cleanup 合同：成功删除报告与目录；删除失败必须使最终门禁非零并在 stderr 报告；原始 test failure 与 cleanup failure 同时发生时两者都报告；runner 不调用中途 process.exit。新增 fixture：symlink/path replacement race、rmSync 抛 EACCES/EIO、report 被替换为 symlink/directory、temp dir 创建失败、test child timeout/signal（`RELEASE_SECURITY_TIMEOUT_MS` 可注入）与成功/失败路径零残留验证。

### 文档与审计合同（WP-G）

ROADMAP 与 CHANGELOG 将 M28 中超出实际实现的四项表述（"收到 signal 后不得输出完整成功声明"、"全部 M28 security tests zero-skip"、"journal durability"、"完整自动恢复"）标记为 M29 strengthening/superseded；不修改已发布 v1.1.9 tag 或 Release notes 资产。PR 模板记录 base SHA/tree、final head SHA、push 次数、每次 CI URL/head/conclusion、最终成功 CI head_sha、checked_sha/checked_tree、merge SHA/tree、tree equality、security runner 实际覆盖文件列表、passed/failed/skipped/todo、temp residue、signal stress 次数/平台、journal crash matrix 数量、hygiene 两个 size 指标各自语义。
