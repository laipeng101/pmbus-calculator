# PMBus Calculator v1.1.9

PATCH release — Release recovery integrity、zero-skip fail-closed、signal/lock lifecycle 与 journal durability（M28）。

## 概述

v1.1.9 对 v1.1.8 的发布管线进行 M28 加固。**v1.1.8 的线上 Release/Pages 资产本身正确且未做任何回滚、tag 移动或资产覆盖**；修复的是 v1.1.8 中经修改前探针实证的十项管线缺陷：COMMITTED 恢复接受非 ZIP 文件并删除唯一有效 backup、无 backup 的已提交 journal 无法恢复、zero-skip runner 在报告缺失/损坏时仍可 exit 0、runner 临时报告清理位于 process.exit 之后永远不可达、SIGINT/SIGTERM 释放锁但不终止工作且退出码被 main 覆盖、lock/journal writeSync 返回 0 时无限循环、journal 的 version/path/hash 未与当前事务及磁盘资产严格绑定、Python ZIP helper 不验证 manifest entry 名、--force/--recover/--recover-lock 冲突组合未明确拒绝。

## 修复

### 恢复状态机以 journal 为唯一事实来源（WP-A）

`recoverTransaction` 必须先读取并严格验证 journal，再依据 journal state + output 是否存在 + backup 数量决定动作，不再先要求 backup。COMMITTED + output + backup 时对 output 执行完整 reverify（asset pair、SHA256SUMS、verify_release_zip.py、版本合同、实际 hash 等于 journal.newSha256），全部通过后才可删除 backup，任一失败保留 output/backup/journal 并返回 manual audit。COMMITTED/BACKUP_CLEANED + output + 无 backup（首次发布 journal.delete 失败或已完成 backup cleanup 的正式恢复路径）完整验证 output 与 journal.newSha256，成功时只清理 journal，失败时保留 output/journal 返回非成功。PRE_COMMIT + 无 backup 明确区分首次发布，只允许基于精确 journal/path/hash 采取保守动作，无法证明所有权时 manual audit。PRE_COMMIT + backup 先深度验证 backup、再恢复、恢复后再次完整验证，失败不删除最后一个有效副本。journal 不得仅靠 state 字符串决定删除资产。

### journal 绑定与耐久性（WP-B）

`validateJournal` 现在验证：journal.version 等于 package.json version、outputPath 精确等于规范化的 release-output、backupPath 为 null 或安全单段名称并与唯一实际 backup 精确一致、禁止绝对路径/.. /反斜杠/路径分隔符、oldSha256/newSha256 必须是小写 64 位十六进制、state 与 backupPath/oldSha256/newSha256 的必需字段组合一致、updatedAt 为严格 ISO 时间。抽取 `writeAllSync`：writeSync 返回 0、负数、NaN、非整数或大于 remaining 均立即失败，不得无限循环；lock 创建失败时只删除自己创建的 inode；journal 写失败不得把部分 journal 提升为正式 journal；close/fsync/rename 错误全部有负向测试；journal rename 后按平台能力 fsync 父目录，无法保证时明确报错或文档化边界。

### zero-skip runner 真正 fail-closed（WP-C）

重构 `scripts/run-release-security-tests.mjs`：不在中间调用 process.exit()，main 返回退出码、顶层最后设置 process.exitCode；report cleanup 位于 try/finally，在成功、测试失败、解析失败、timeout、signal、异常路径全部执行；report 缺失、空、损坏、字段缺失、字段非有限整数、统计不一致，无论 Vitest status 是多少都必须 exit nonzero；result.status 必须严格为 0，null/signal/timeout/spawn error 都失败；total > 0、failed === 0、skipped === 0、passed + failed + skipped 与 total 一致；输出失败测试名，但不得因 malformed assertionResults 自身崩溃。为 runner 本身增加独立单测，不只测试底层 generator；运行真实 `npm run test:release-security` 后确认 /tmp 无报告残留。

### SIGINT/SIGTERM 与锁生命周期（WP-D）

核心规则：进程仍可能修改 staging/output/backup/journal 时绝不能提前释放锁；signal handler 只记录终止请求，锁由统一 finally 在所有写操作停止后释放；若无法安全即时中断同步 Python/文件操作，应保守地保持锁、完成当前原子阶段后停止，不得制造 split-brain；最终 SIGINT 返回 130、SIGTERM 返回 143；main 不得用 runCli 的 0 覆盖 signal code；收到 signal 后不得输出完整成功声明；lock release 失败保持 recoverable metadata 并返回非零。真实子进程测试：使用慢速可控 helper 在持锁期间发送 SIGINT/SIGTERM，另一个 generator 在第一个进程完全停止前绝不能获得锁，第一进程退出码精确为 130/143，最终状态只能是完整回滚、已提交且完整验证、或保留 journal/lock/backup 供显式恢复，禁止"锁已释放但原进程继续写文件"。

### ZIP helper 自身 fail-closed（WP-E）

`_zip_helper.py` 直接验证 manifest entry：非空 POSIX relative path、禁止绝对路径、禁止 .. segment、禁止反斜杠、禁止空 segment 与 "." segment、禁止重复 entry，与 release-artifact-contract 的 ZIP entry policy 保持一致。非法 manifest 或任一文件失败时删除 partial ZIP。补充同 inode、同大小但读取期间内容变化的策略：至少比较 fstat 的 size、dev、ino、mtime_ns、ctime_ns，无法证明稳定快照时失败，不得宣称完整 TOCTOU 防护。

### CLI 与审计（WP-F）

--force、--recover、--recover-lock 必须互斥，任意冲突组合在创建 lock 前 exit 2；未知参数仍在创建 lock 前失败。PR 描述在 merge 前必须包含 source branch HEAD、CI URL、Actions API head_sha、CI conclusion、checked_sha、checked_tree；merge SHA/tree 只放最终报告，merge 前不虚构；如发生第二次 push 或失败 CI 必须如实记录，不得声称 single push。

## 已知限制

- DIRECT device-datasheet profiles：需要真实器件数据手册，blocked。
