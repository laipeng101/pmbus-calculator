# PMBus Calculator v2.5.2

PATCH release — 修复非 LINEAR 共享 VOUT_MODE（VID / DIRECT / IEEE Half）在 LINEAR16
页面被隐式替换为 `0x18` 后继续编码的 P1 缺陷，并隔离默认 E2E 套件与 deployment smoke
的口径。

> 2026-08-27 · PATCH（无新功能，行为修正）· PMBus Rev 1.3 / SMBus 3.0

## Fixed

- **非 LINEAR 共享 VOUT_MODE 隐式回退 0x18 继续编码（P1）**：v2.5.1 中共享字节为
  非 LINEAR 时，LINEAR16 页面按 `DEFAULT_LINEAR_VOUT_MODE = 0x18` 计算——
  复现向量：`0x20 + SLINEAR16`，输入物理值 `1` 生成 `raw=0x0100`、结果 `1`、量化
  误差 `+0.000000 (0.0000%)`，仅有「按 fallback 0x18 计算」标注。Part II §8.4 规定
  输出电压相关命令的数据格式由当前 VOUT_MODE 决定，不能静默改用另一个字节。
  修复后 fail closed：
  - `effectiveL16VoutMode` 返回实际共享字节（`source: 'non-linear'`），显示字节
    不再是 `0x18` 替身；
  - `value/set` 对非 LINEAR 共享字节 no-op（两个 payload kind 均不生成 raw、不伪造
    provenance）；结果为 `—`；`nRangeText=null`（无伪 LINEAR 范围）；
    `computeQuantizationOutcome` 返回 null；计算步骤显示 fail-closed 警告，无伪 N、
    伪 V、伪结果、伪量化步骤；
  - VID（format `01`）阻断卡引用 §8.4 与 §13.3/§13.4：该命令组合被禁止、不生成
    word；DIRECT / IEEE Half 显示需要相应 format/profile/coefficients、不猜测 N；
    invalid-parameter / invalid-combination 保持 error 级；
  - 恢复路径唯一且显式：「应用默认 VOUT_MODE」按钮真实写入
    `state.voutMode.byte=0x18`（source 回到「已关联」）并清除旧 provenance，此后
    输入、范围、结果与量化读数恢复（`value/set 12 → 0x0C00`）。
- **默认 E2E 套件与 deployment smoke 口径隔离**：默认 `playwright.config.ts` 排除
  `deployment.spec.ts`，URL-gated 的 Pages smoke 不再混入默认 passed 数；部署用例
  只由 `playwright.deployment.config.ts` 对正式 URL 运行。新口径：默认
  **326 tests / 15 files**（无 skip），deployment **4 tests / 1 file**。
- **测试基建**：`check-repo-hygiene` / `specifications` / `classify-ci-scope` 的嵌套
  git fixture 仓库不再继承 `git commit` 钩子导出的 `GIT_*` 环境变量（否则 pre-commit
  下 fixture 的 git 命令会寻址外层仓库的 index）。

## 保留的 v2.5.1 合法路径（回归确认）

- `0x18 + ULINEAR16` / `0x18 + SLINEAR16` 正常编码与量化读数。
- `0x98 + ULINEAR16` relative positive ratio：无 nominal 时不伪造最终电压。
- `0x98 + SLINEAR16`：物理输入可达、bit7 N/A、`3.3 → 0x034D`（quantized −0.0237%）、
  手动 Y_s 清 provenance、`200 → 0x7FFF` saturated/error。
- DIRECT 零分母、HALF overflow/tiny 向量全部保持。
