# PMBus Calculator v2.6.1

PATCH release：发布完整性、帮助系统契约与 CI 效率加固——Pages 手动部署来源
绑定、术语浮层卸载状态修复、术语放置覆盖单一事实源、ARIA 关闭态合同文档
纠偏、light-tier CI 去浪费与语义 E2E 双 worker。

**本版本不改变任何 PMBus 数据格式的数学语义**：LINEAR11/LINEAR16/DIRECT/HALF
的表示关系、舍入策略、signed-zero 与特殊值合同、provenance 与资源边界全部
不变。全部受保护算法（`decodeLinear11`/`encodeLinear11`/`findBestLinear11`/
`decodeLinear16`/`encodeLinear16`/`decodeDirect`/`encodeDirect`/`decodeHalf`/
`encodeHalf`/`parseVoutMode`/`calculatePEC`）零变更。

## 变更范围

1. **Pages 手动部署来源绑定（安全加固）**：`workflow_dispatch` 部署路径此前
   在 checkout 默认 ref 之后才解析输入 tag——验证脚本来自 dispatch ref 的树，
   而非被部署 tag 的树。现在 tag 解析与 SemVer 验证前置于 checkout（纯
   shell），dispatch 必须在被部署 tag 的 ref 上发起，checkout 显式绑定解析
   出的 tag，并在 checkout 后校验 annotated tag / 40 位 peeled commit /
   `HEAD` 一致与 Release 元数据 `tag_name` 完全匹配；验证脚本因此始终来自
   被部署 tag 的不可变树。`release published` 路径行为不变；immutable
   Release 资产验证、SHA256SUMS/ZIP 安全检查、Pages environment、部署后
   remote smoke 与 action SHA pinning 全部保留。合同测试
   `tests/pages-workflow.test.ts`（先红后绿）钉住全部条款。
2. **术语浮层卸载状态修复**：`TechnicalTerm` 此前没有卸载清理——当其浮层是
   active surface 时被卸载（典型：Ctrl+1..5 切走仅该模式渲染的术语），
   provider 会残留 detached trigger 引用并泄漏共享 document 监听（jsdom
   合同实测 added=2/removed=0）。修复与 `ControlTooltip` 对称（卸载时
   `closeIfActive`）。新增 `src/components/help/help-overlay.test.tsx` jsdom
   合同（真实 Provider + TechnicalTerm + 只读 Probe + 条件卸载，StrictMode
   下监听 add/remove 对称）与应用级 E2E（真实 Ctrl+2 切换、无残留 portal、
   全局单开、Escape 恢复到有效触发器）。诚实说明：React 19 的实例级
   `useId` 让重挂载拿到不同 surfaceKey，缺陷在应用层无可见 DOM 症状——
   provider 状态合同是本缺陷的失败门，E2E 为回归锁。
3. **术语放置覆盖单一事实源**：v2.6.0 的 `TERM_PLACEMENT_SURFACES` 只被单测
   读取、还引用了不存在的 testid，E2E 另持一份手写清单——「由 registry 契约
   守护」的说法不成立。现已删除该清单与仅检查非空字符串的单测；E2E 直接
   导入 `GLOSSARY_TERM_IDS`，在页头、五种模式、结果区、显式编码请求、
   relative、VID 与展开的命令参考等真实页面状态中从
   `data-testid="term-trigger-<id>"` 累计出现过的术语 id，断言与 registry
   完全相等（23/23，无缺失、无未知 id）。代表性交互用例保留。
4. **ARIA 关闭态合同文档纠偏**：术语触发器 collapsed 态实现输出
   `aria-expanded="false"`（常见 disclosure 语义），文档曾写「关闭时不声明
   expanded」；保留实现、修正 `docs/UI_CONVENTIONS.md` §7，E2E 补齐关闭态与
   Escape 后的属性断言。控件 tooltip 仍无 `aria-expanded`（既有守护不变）。
5. **规范引用精度**：SMBus / LE 术语的「word 线上低字节在前」引用收窄为
   「Part II §7.6 对浮点数据明示」（通用传输规则来自 SMBus/PMBus）；对照
   PMBus 1.3 Part II §7.2/§7.3/§7.4/§7.6/§7.6.2/§8.3/§8.4.1–8.4.4/
   §8.5.1–8.5.3/§13.3–13.4 的复核未发现实现与规范冲突。
6. **CI 效率（数据驱动）**：
   - e2e job 的 `npm ci` 在 light-only 变更时跳过（fail-closed 门不变，
     quality 的 light gates 安装保持无条件，workflow_dispatch 恒 full）。
   - desktop 语义 E2E 在 CI 以 2 个 worker 运行。本地无 retry 实验：
     1-worker 105s → 2-worker 三轮 59/59/58s（中位改善 44%），零 flake、
     零 retry、326 逻辑测试数守恒；六个高时序风险 spec（control-tooltip、
     terminology-popover、input-blur-transactions、input-interaction、
     result-stress、direct-fidelity）的 2-worker × repeat-each=10 压力共
     1210 次执行零失败、零 skip。mobile / release / visual 的 worker 策略
     不变；决策由 `tests/playwright-default-config.test.ts` 钉住。

## 诚实陈述

1. **数学语义零变更**：未触碰全部受保护 PMBus 算法及其 golden case；数值
   呈现真值不变。UI 预期无像素变化：visual 28 张基线 0 新增 / 0 修改 /
   0 删除。
2. **本仓库产品代码变更仅两处**：`TechnicalTerm.tsx` 新增与 `ControlTooltip`
   对称的卸载清理；`terminology.ts` 两处规范引用文案收窄。其余全部为
   workflow、测试与文档。
3. **双 worker 证据边界**：实验在本地 Apple M4（10 核）完成；CI runner 为
   4-vCPU ubuntu，绝对耗时不同，但套件 fullyParallel、每用例独立 browser
   context、无共享端口/文件/localStorage/clipboard，重复实验未观察到任何
   时序竞争。若未来 CI 上出现无法定位的 E2E 时序失败，恢复 1 worker 是
   允许的第一排查动作（需按本文件的证据纪律重新实验）。
4. **删除口径**：仅删除零引用的 `TERM_PLACEMENT_SURFACES` 清单与其单测；
   不删除任何 visual 基线、legacy HTML、lockfile、规范 manifest、
   release 文档或历史 tag。
