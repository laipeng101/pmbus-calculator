# PMBus Calculator v2.5.10

PATCH release — 修复「自动编码的严格最近值」与「输入到状态的数据真实性」
两类产品缺陷，并给发布下载器补上真实、可证明的总时限。

> 2026-08-29 · PATCH（向后兼容 bugfix）· PMBus Rev 1.3 / SMBus 3.0

## 诚实声明：四类变化的确切性质

1. **LINEAR11 严格最近值是仓库自动编码策略修复，不是 PMBus 规范变更**。
   PMBus Part II §7.3 只规定表示关系 `X = Y × 2^N`，从未规定 host-side
   自动选 N/Y 的舍入或 tie 规则。旧实现用固定绝对容差 `1e-15` 把严格不同
   的误差归并为并列、再偏好较小 `|N|`，使恰在 2^-17 中点之上的请求
   （如 `0.0000076293945313`）编码为 `0x0000`，而 `0x8001` 严格更近
   （误差小约 1.0000071e-16）；负向对称输入同样错误。现在返回严格最小
   误差的表示；bit 级完全相等的误差并列遵循一条显式、已文档化、可测试的
   确定性 tie policy（更小 `|N|`，同 `|N|` 取 N 升序先见者）。锁定 N 的
   手动路径、饱和边界、常规值编码与 HALF ties-to-even、DIRECT legacy
   舍入都不变。
2. **十进制输入下溢是输入真实性修复，不是把 PMBus 语义强加给输入**。
   `Number('1e-400')` 是 `+0`——这是 JavaScript binary64 的事实，不是
   PMBus 规则。旧解析层把该转换结果当作「用户请求了零」提交（raw
   `0x0000`/`0x8000`、provenance 改写、量化误差伪造为零），非零请求的
   量级信息在解析层丢失。现在这类文本（语法完整、尾数含非零数字、
   Number 结果为 ±0，如 `1e-400`、`2e-324`）是明确的输入范围错误：保留
   草稿与错误、不提交、不改旧 raw / 请求 / 标称。真零文本
   （`0e-400`、`-0e400`、`-0.0e-999`、`-.0e-999`）与最小 subnormal
   （`5e-324`、`3e-324`）行为不变；HALF `2^-25` 等「请求本身可在 Number
   中表示、编码到 binary16 量化为零」的量化合同不变——那是合法请求的
   格式量化，不是输入解析错误。不引入任意精度编码器，不改编码算法。
3. **relative 乘法下溢诊断是 v2.5.9 已有的派生修复，本轮未改动它**。
   两个非零有限数相乘下溢为 0 的派生诊断（`resolveRelativeVoltage`）
   自 v2.5.9 起存在；本轮的输入下溢修复只是让「虚假的零请求」不再从
   输入层产生，两类错误来源（输入下溢 vs 派生下溢）的文案、状态与测试
   保持分离。
4. **发布链路两项运维/工具修复（产品行为不变）**：
   - 发布下载器此前每次 fetch 新建 5 分钟超时，最坏累计约 30 分钟，而
     Pages job `timeout-minutes: 20` 会先被平台终止；现在整个下载操作
     共享一个 5 分钟累计预算（重试与 backoff 消耗同一预算、不重置），
     每次 fetch 的 AbortSignal 取剩余预算，预算耗尽以退出码 10 与可识别
     诊断终止；重试仅限瞬时故障（网络错误与 HTTP 408/429/5xx）。
   - draft Release 资产 URL 的占位 tag 段（`untagged-<hex>`）在 publish
     前真实存在：接受该形式的修复（PR #70）在 v2.5.9 publish 前已合入
     main，但**不在不可变的 v2.5.9 tag 产品树中**，本版本正式纳入发布
     源码；占位段正则同时从 `untagged-\w+` 收紧为实际观察到的
     十六进制形式，published（Pages）模式保持严格 tag 路径。发布顺序
     draft → 上传 → 回验 → publish、元数据只作为数据（无
     `source`/`eval`）、退出码合同全部不变。

## Fixed

- **LINEAR11 自动编码偏离严格最近值（P1）**：`findBestLinear11` 移除
  固定绝对 epsilon，返回候选集合中 `|X − Y×2^N|` 严格最小的表示；
  exact tie 采用确定性 tie policy 并登记于 DOMAIN_MODEL §2.1。测试覆盖
  正负 6 向量、nextUp/nextDown 中点邻接、跨 N/奇偶 Y 的中点邻接矩阵、
  65536 全码 oracle、reducer/view-model 一致性、真实物理值 Playwright
  事务、锁定 N 与正负饱和回归。
- **非零十进制输入下溢静默提交为 ±0（P2）**：`classifyFloatText` 增加
  可判别 `underflow` 分类（按完整十进制语法识别尾数是否数学非零，不用
  指数阈值硬编码）；ValueInput / NominalVoutInput 消费共享分类，错误
  独立、文案与派生下溢区分；reducer fail-closed。测试覆盖正负/真零/
  最小 subnormal/溢出/非法全矩阵（含 `Object.is(-0)`）、逐模式 reducer
  no-op、HALF `-0e400 → 0x8000` 与 `5e-324` 合法量化、relative L16 的
  标称保持与两条下溢路径、fill/逐键/Enter/真实剪贴板粘贴/untouched
  blur 事务、1280/390/360px 无横向溢出。
- **发布下载器缺少真实总时限（P2 运维）**：整个操作共享 5 分钟累计
  预算；每次 fetch 取剩余预算；重试限瞬时故障、有界、backoff 计入
  预算；两项资产 size 校验通过后才写盘。离线测试以可注入
  预算/时钟/sleep 确定性证明：单请求挂起到剩余预算、跨资产共享预算、
  不因重试获得新预算、408 重试、无部分写盘。
- **draft 占位 URL 合同收紧（工具修复）**：`untagged-[0-9a-f]+` 与注释、
  夹具一致；published 模式严格；下划线/大写/外来 repo/资产名/发布后
  占位段仍被拒绝。
