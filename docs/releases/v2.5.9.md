# PMBus Calculator v2.5.9

PATCH release — 修复「输入到结果的数据完整性」与「验证到发布的证据完整性」
两类缺陷：无效草稿在失焦时被有损修复成有效提交（invalid → value）、
relative 电压派生缺少溢出/下溢范围诊断、发布元数据被当作 shell 程序消费
（防御性加固）。

> 2026-08-28 · PATCH（向后兼容 bugfix）· PMBus Rev 1.3 / SMBus 3.0

## 诚实声明：行为变化的确切范围

本轮**没有**重写任何编码/解码数学：HALF round-to-nearest-even、
LINEAR11/16 饱和边界、DIRECT legacy 舍入、字节序与复制合同、SLINEAR16
offset 语义全部不变。变化的是此前错误的输入处理、结果呈现与发布消费方式：

1. **无效草稿的失焦行为变了**：旧实现先删尾字符再分类，`NaN.`/`NaNe`/
   `Infinitye`/`2..` 在 blur/Enter 时被"修复"并提交（HALF raw `3C00` 起：
   `NaN.` → `7E00`、`Infinitye` → `7C00`、`2..` → `4000`，错误消失）。
   现在非法草稿失焦后**保留草稿与错误**：不提交、不改 raw、不创建新
   provenance、不清掉原有 provenance、不静默恢复旧显示。合法前缀的即时
   提交保留（逐键输入 `NaN.` 时前缀 `NaN` 仍即时提交 `7E00`，末点报错且
   blur 保留草稿——断言的是无效事件及其失焦不提交，不是会话回滚）。
2. **过渡态更严格了**：`e`、`e+`、`e-`、`.e`、`-.e`、`-e+`、`1ee`、
   `1e++`、`NaNe` 不再是合法过渡态（旧正则允许裸 `e` 在 blur 归一成 0）。
   合法过渡态（空串、单独符号、裸点、含数字尾数 + 未完成指数）的归一化
   结果不变：`.`/`+.`→0、`-.`→-0、`+`/`-`→0、`1e`/`1e+`/`1e-`→1、
   `12.5e-`→12.5、`-0e+`→-0；`1.` 本就是完整有效值。
3. **relative 派生的范围状态可见了**：`V_NOM × R` 乘法溢出（如
   nominal=`1e308`、ratio=2）不再显示正常样子的 `Infinity`，而是结果卡与
   计算步骤显示 `—` 加明确说明；非零因子下溢为零不再伪装成精确 0。输入
   不被裁剪或拒绝——大而有限的参考值照常提交，范围错误属于派生计算。
   nominal=0 或 ratio=0 的真零不受影响；`1e-400 → 0` 的输入层合同不变；
   SLINEAR16 offset 与 non-LINEAR fail-closed 分支不受影响。
4. **发布链路消费方式变了（产品行为不变）**：Pages workflow 不再用
   `source` 消费 verifier 输出（此前元数据文本中的命令替换会被执行——
   仅在离线夹具中证实，实际 `browser_download_url` 由 GitHub 生成，无
   证据表明普通外部攻击者可控，故为防御性加固）；改为 JSON 数据接口 +
   Node 下载器，URL 按 canonical 合同用解析器校验。发布顺序
   draft→上传→回验→publish 与退出码合同不变。

## Fixed

- **无效草稿失焦变有效提交（P1）**：`fixFloatTextOnBlur` 不判断原始分类
  就删除末尾点号或 `e/e+/e-`，`ValueInput`/`NominalVoutInput` 先修后分类，
  于是 `invalid → value` 甚至 `invalid → transitional → 清错恢复旧显示`。
  现在过渡态严格限定为「空串、单独正负号、裸点简写、含数字的十进制尾数 +
  未完成指数」；新增共享失焦决策 `resolveFloatTextOnBlur`（分类在先，
  归一化必须得到完整值否则 fail-closed）；两个组件的 blur/Enter 消费同一
  决策，不再各自维护修复逻辑。invalid/out-of-range 失焦保留草稿与错误；
  未编辑的第二次失焦仍是严格 no-op；真实修复后错误清除；空串语义由字段
  决定（物理值 blur 提交 0，标称 blur/Enter 清除为 null）。
- **relative 电压派生缺少范围诊断（P2）**：view-model、
  formula-presentation、calculation-steps 与物理值复制各自直接相乘。现在
  共享分类器 `resolveRelativeVoltage`（`src/app/relative-voltage.ts`）
  区分 missing-reference / finite / overflow / underflow，四个表面 +
  warning 全部消费同一分类：溢出/下溢显示 `—` 与共享说明文案，公式保留
  nominal 与比值、C 宏注释不输出虚假电压，「物理值」复制禁用并给出可访问
  原因（Hex/LE/BE 复制不受影响）；错误消除后自然恢复，无需刷新或切换
  模式。
- **发布元数据数据/代码边界（P2 加固）**：`release-assets-verify.mjs`
  stdout 改为单一 JSON 对象（诊断走 stderr），新增 `--repo` 参数；URL 由
  `scripts/release-url-contract.mjs` 用 URL 解析器按 canonical 合同校验
  （scheme/host/path、userinfo、query/fragment、控制字符、路径逃逸、
  非规范编码），资产名必须是安全 basename；新增
  `scripts/download-release-assets.mjs` 作为真实消费（静态 JSON 读取、
  URL 二次校验、字节数核对、有界瞬时重试），Pages workflow 弃用
  `source release-assets.env`。readiness 校验只证明元数据满足前置条件，
  竞态防护仍依赖 draft→上传→回验→publish 顺序；下载字节数、SHA-256 与
  ZIP 合同检查全部保留。
