# PMBus Calculator v2.5.7

PATCH release — 修复 HALF 负零简写丢失符号（`-.0` → `+0`/`0x0000`）的 P1 缺陷；
把 v2.5.6 的 untouched-blur 事务语义推广到全部共享输入；已选语义控件点击保持
幂等（不清除 provenance）；把 `0x18` 的表述从「默认 VOUT_MODE」纠正为「计算器
LINEAR 示例」。

> 2026-08-28 · PATCH（向后兼容 bugfix）· PMBus Rev 1.3 / SMBus 3.0

## 诚实声明：显式编辑行为与全部计算语义保持不变

v2.5.7 不改变任何编码/解码数学（`encodeHalf` round-to-nearest-even 未动）、
舍入、饱和、字节序或复制合同。用户**真实编辑**后的提交行为（即时提交、blur
规范化、HALF 显式重输 `NaN` canonical 化为 `0x7E00`）与之前完全一致；修复移除
的只是「未发生任何编辑时 blur 也会提交」与「重复选择已选语义控件也会清除
provenance」这两条错误路径。0x18 的初始/恢复数值行为不变，纠正的是名称与
表述。

## Fixed

- **HALF 负零简写丢失符号（P1）**：此前 `-.0`、`-.00` 经
  `/^[+-]?\.0*$/` 分支直接 `return 0`，符号被覆盖——IEEE 754 binary16 的 `+0`
  与 `-0` 是不同原码（`0x0000` / `0x8000`，Part II §7.6），`Number('-.0')` 本是
  `-0`；§7.6.2 要求设备读回主机写入的精确 IEEE 编码，不能用「数值都等于零」
  掩盖 sign bit 丢失。现在 `-0`、`-0.0`、`-.0`、`-.00`、`-0e3` 解析为真正的
  `-0`（`Object.is` 断言），HALF 编码 `0x8000`、显示 `-0`；`0`、`+0`、`0.0`、
  `.0`、`+.0`、`0e3` 保持 `0x0000`；裸 `.`/`+.`/`-.` 为编辑过渡态（不提交、不
  创建 provenance），blur 规范化保留符号：`.`/`+.` → `0`，`-.` → `-0`。
- **untouched blur 重写共享输入状态（P1）**：v2.5.6 只事务化了物理值输入；
  raw Hex、L11 Y/N、DIRECT Y/m/b/R、SLINEAR16 Y_s、L16 V、VOUT_MODE expert
  Hex/N、标称参考值在 untouched blur 时仍无条件 `onCommit`，即使值完全相同
  也会经 reducer 清除量化 provenance（如 L16 value `1` → raw `0100` 后只
  focus/blur raw Hex，provenance 消失）。现在全部共享输入共享同一事务判定
  （`src/app/input-transaction.ts`）：当前 focus 会话内没有任何真实 `onChange`
  时 blur/Enter 严格 no-op——不派发、不改写 raw/参数/VOUT_MODE 字节、不清除
  provenance、不清除仍存在的字段错误；显式清空后 blur、显式重输相同值、
  粘贴、非法文本修复仍是真实事务并按既有合同提交。
- **已选语义控件点击清除 provenance（P2）**：点击当前已选中的「绝对值/相对值」
  radio 会无条件派发 `vout-mode/set-relative` 并清除量化请求来源。现在
  `setVoutModeByte` 对同字节写入幂等（返回同一 state 引用），composer 的
  semantic radio 仅在目标状态不同时派发；真正改变字节时仍清除失效 provenance
  （相反路径有 reducer 与 E2E 断言）。
- **`0x18` 默认值表述纠偏（P2）**：`DEFAULT_LINEAR_VOUT_MODE` 注释仍声称
  non-LINEAR fallback，UI 称「应用默认 VOUT_MODE」，与 v2.5.2 起 fail-closed
  行为矛盾。Part II §8.3 只定义 VOUT_MODE 位布局与合法组合，不存在 PMBus
  标准默认字节；器件可在制造时固定 Mode/Parameter 并拒绝写入。常量更名为
  `CALCULATOR_LINEAR_EXAMPLE_VOUT_MODE`、action 更名为
  `l16/apply-calculator-linear-example`，删除 stale fallback 说明；用户可见
  表面统一表述「应用计算器 LINEAR 示例 0x18（absolute、N=-8）」并明示不是
  PMBus 规范默认值、不代表真实器件一定接受 VOUT_MODE 写入；反词测试禁止
  「规范默认/器件默认/自动回退」措辞回归。
