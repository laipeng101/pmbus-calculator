# PMBus 换算规则

以 PMBus 1.3 / 1.3.1 和 SMBus 3.0 为参考。查阅原文时按[规范获取说明](../document/README.md)下载对应的 Part。计算器负责数值换算、VOUT_MODE 解读和命令查询。换算入口见 [pmbus-math.ts](../src/legacy/pmbus-math.ts)。

## 1. 数据格式

| 格式     | 换算关系                                           | 字段                                             |
| -------- | -------------------------------------------------- | ------------------------------------------------ |
| LINEAR11 | $X = Y \times 2^N$                                 | 5 位有符号指数 N，11 位有符号数据 Y              |
| LINEAR16 | $X = Y \times 2^N$                                 | 16 位数据，符号由命令定义，指数来自 VOUT_MODE    |
| DIRECT   | $X = \frac{1}{m}\left(Y \times 10^{-R} - b\right)$ | 通用 DIRECT 使用 16 位有符号 Y，m/b/R 由器件提供 |
| HALF     | IEEE 754 binary16                                  | 1 位符号、5 位指数、10 位尾数                    |

PMBus Part II §7.2 / §8.1.2 规定，采用 IEEE Half 的器件，其数值命令都用 Half。采用 LINEAR 或 DIRECT 的器件，其数值命令均不使用 Half。各换算页可独立使用。器件采用的格式以器件资料为准。

## 2. 饱和与错误处理

### 2.1 LINEAR11

- Y 的范围为 `-1024..1023`，N 的范围为 `-16..15`。手动锁定指数时按该 N 判断可表示范围。自动选指数时以 N=15 的两端为整个格式的边界。超出范围时钳位并报告饱和。两个边界编码本身合法。
- 自动选择 N 和 Y 时最小化 `|X − Y × 2^N|`。只有按 binary64 算出的误差完全相等时才比较 `|N|`，优先取较小者，仍相等则取升序枚举时先遇到的 N。Part II §7.3 定义表示关系，这一并列规则由计算器定义。

### 2.2 LINEAR16

先判断共享 VOUT_MODE 是否为 LINEAR，再解释命令数据字。VID、DIRECT、HALF 或无效配置保留实际配置和原始字，禁止在 LINEAR16 页通过物理值输入编码。用户可主动应用 LINEAR 示例 `0x18`。[配置规则](#3-vout_mode)

| 命令数据格式   | 位型和换算                                                           | 物理值编码 |
| -------------- | -------------------------------------------------------------------- | ---------- |
| 绝对 ULINEAR16 | 无符号 `0..65535`，电压为 $Y \times 2^N$                             | 支持       |
| 相对 ULINEAR16 | 无符号，先算比值 $Y \times 2^N$，再乘 VOUT_COMMAND 标称电压          | 禁用       |
| SLINEAR16 偏移 | 16 位二补码 `-32768..32767`，偏移为 $Y \times 2^N$，bit 7 不影响结果 | 支持       |

- 相对 ULINEAR16 的比值须为正。原始字为零时仍显示比值 `0`，并提示规范限制。未提供标称电压或乘积发生溢出、下溢时，保留比值并省略最终电压。乘积确实为零时显示零电压。
- SLINEAR16 用于 VOUT_TRIM / VOUT_CAL_OFFSET（Part II §13.3 / §13.4）。例如 `0x98` 的 N=-8，偏移可编码范围为 `-128..127.99609375`，输入 200 饱和到 `0x7FFF`。
- 手动设置无符号 V 或原始字时钳位到 `0..65535`。Hex 支持首尾空白和可选 `0x` 前缀，最多四位十六进制数字。空输入按 0 处理，前缀后缺数字或格式错误时保留原始字并提示。

### 2.3 DIRECT

- 通用 DIRECT 按 Part II §7.4 把 Y 解释成 16 位有符号数，例如 `0xFFFF` 表示 `-1`。Part II §8.1.1 / §8.4.3 中输出电压相关命令的无符号规定属于该命令的上下文。
- m 和 b 为 16 位有符号整数，R 为 8 位有符号整数。m=0 时公式无定义。无效系数留在编辑字段中，改正后清除该字段错误。系数编辑保留原始字，错误只在 DIRECT 模式显示。
- 编码将 $(mX+b)\times 10^R$ 就近取整，中点向正无穷方向取整，再钳位到 `-32768..32767`。输入按十进制文本精确求有理数。表示值、范围端点和量化分类也用同一套精确算术，m 为负时按解码后的数值排序端点。[direct-exact.ts](../src/app/direct-exact.ts)
- 精确输入按 trim 前的原始字符数限制在 4096 字符内。长度、语法和指数移位在构造 BigInt 前检查，移位下界按去除尾零后的实际值判断。正常的负零和带指数的零可读。超长候选整体拒绝，保留旧原始字和请求。
- 显示文本重输会改写 Y 时，提示是浮点表示还是显示位数造成差异。复制优先使用精确的有限小数，否则使用能重输得到原 Y 的近似文本。[重新输入与复制的设计理由](adr/0007-direct-text-reentry-contract.md) · [界面约定](UI_CONVENTIONS.md#量化误差和复制)

### 2.4 HALF

- 遵循 IEEE 754 最近偶数舍入。次正规数的步长为 $2^{-24}$，`|X| ≥ 65520` 的有限输入舍入为相应的无穷，NaN 编码为 `0x7E00`，零保留符号。
- PMBus Part II §7.6.2 要求设备读回主机此前写入的值时返回原 IEEE 编码，包括 NaN 和无穷。设备期待数值时，将写入的 NaN 判为无效数据并依 §10.8 报告通信故障。写入的正、负无穷分别按正、负满量程处理。设备可在数值不可用时返回 NaN。测量结果中的正、负无穷分别表示在相应方向饱和。
- 解码原始字和编码输入均可展示上述解释。有限输入编码溢出时，同时显示量化溢出和已编码特殊值的含义。[half-special-semantics.ts](../src/app/half-special-semantics.ts)

## 3. VOUT_MODE

Part II §8.3 定义 bit 7 为绝对或相对，bits 6:5 为数据格式（00 LINEAR、01 VID、10 DIRECT、11 IEEE Half），bits 4:0 为参数。LINEAR 的 N 是该参数对应的 5 位有符号数，只从共享字节派生。[解析与组装](../src/legacy/vout-mode.ts)

- bit 7 配置的是 §8.5 所列的输出电压阈值、裕量和 POWER_GOOD 命令。VOUT_COMMAND 仍提供标称电压，相对命令的实际电压由标称电压乘以比值得到。
- DIRECT 和 Half 的参数须为零（§8.3 Table 2）。用 DIRECT 换算须提供器件的 m/b/R，Half 直接按 binary16 换算。两种格式计算实际电压时，若使用相对值还须提供标称电压。
- VID 仅适用于绝对配置（§8.5.3）。普通 VID 解码需要相应代码表。Table 3 的 `00h` 为未使用，保留类型须区分表中明列与未列出。制造商自定义 `1Eh/1Fh` 的结构合法，但仍需器件资料。VOUT_TRIM / VOUT_CAL_OFFSET 的偏移语义禁止 VID。
- VOUT_MODE 页完整保留用户编辑的原始字节，包括无效组合。语义控件及显式规范化操作生成与所选格式相符的字节。`0x18` 是计算器的绝对 LINEAR 示例（N=-8）。器件可固定相应配置。
- [格式要求](../src/app/vout-mode-requirements.ts)负责区分结构合法、缺外部数据和可计算三种判断。[LINEAR16 数据格式判断](../src/app/l16-payload-contract.ts)处理字节与命令数据格式的组合，[LINEAR16 派生值](../src/app/l16-derivation.ts)供结果、公式、步骤、复制和量化共用。设计理由见 [ADR 0006](adr/0006-canonical-l16-vout-semantic-derivation.md)。

## 4. 原始数据字与字节序

`state.raw` 是无符号 16 位原始字。Hex 输入、位网格、公式、Raw Word 复制和 C 宏使用相同位型。输入 `3412` 得到原始字 `0x3412`。

标准 SMBus Word 事务先传低字节（SMBus 3.0 §6.5.4 / §6.5.5）。PMBus 区域读取 `ZONE_READ` 的命令数据响应在 `DS=0` 时沿用此顺序，`DS=1` 时先传高字节（PMBus 1.3 Part I §5.6.3.2.4，1.3.1 Part I §5.6.3.4.2 Table 2）。

计算器的 Wire Bytes 使用标准 SMBus Word 顺序。原始字 `0x1234` 的 Wire Bytes 为 `34 12`，高字节在前的表示为 `12 34`。两种字节表示分别复制。复制选项不改变原始字、结果或请求。[ADR 0003](adr/0003-canonical-raw-word.md)

## 5. 命令参考

只读命令表取自 [command-metadata.ts](../src/legacy/command-metadata.ts)，记录命令码、事务、长度、类型、单位、格式来源及规范章节。单靠命令名不能确定器件的格式和系数，换算参数由用户按 VOUT_MODE 和器件资料输入。

- `STATUS_WORD` 通常用 Read Word 读取。写入 `0x0100` 只清除 UNKNOWN 位，其余按相应状态寄存器或 `CLEAR_FAULTS` 规则处理。
- `READ_EIN` 用 Block Read。Part II §18.13 描述 6 个数据字节（累加值 2、溢出计数 1、采样数 3），Appendix I Table 31 列为 5。界面从命令数据的 `dataBytesConflict` 字段展示这一差异。

## 6. 编码量化误差

量化分类由 [quantization-error.ts](../src/app/quantization-error.ts) 计算，适用于四个数值格式页。量化误差反映当前编码的表示差，器件准确度另见数据手册（Part II §7.8 / §7.9）。

### 6.1 有效的编码请求

- 最后一次成功提交物理值后，才有可用于计算误差的请求。DIRECT 保存实际用于精确编码的文本。只聚焦再失焦、非法输入或超长输入都不提交请求。例如 HALF 解码 `0x7C01` 后，无编辑的失焦保持原 NaN 位型。
- 手动更改原始字、影响解释的参数或模式会清除旧请求。同一模式或同一 VOUT_MODE 字节的幂等操作不改变请求。LINEAR11 切换自动指数会保留已有请求，原先无请求时也不从解码值生成请求。
- 没有请求，或 LINEAR16 当前配置没有可用的物理值换算时，隐藏误差读数。

### 6.2 编码结果分类

| 状态        | 条件                                   |
| ----------- | -------------------------------------- |
| `exact`     | 有限请求与编码表示值相同               |
| `quantized` | 舍入后的有限表示值与请求有差           |
| `saturated` | 请求超出可表示范围，结果钳位到有限边界 |
| `overflow`  | 有限请求按 HALF 舍入为正或负无穷       |
| `special`   | 显式请求 NaN、正无穷或负无穷           |

误差方向是「请求值 − 表示值」。两值均有限且请求非零时才计算相对误差。非零差值的显示不得舍成零，通用数字格式由 [numeric-presentation.ts](../src/app/numeric-presentation.ts) 提供。读数和复制见[界面约定](UI_CONVENTIONS.md#量化误差和复制)。
